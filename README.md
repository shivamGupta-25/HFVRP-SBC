# Blinkit Delhi-NCR Replenishment Optimiser — User Guide

Plans the nightly replenishment of **361 Blinkit dark stores in Delhi-NCR** from one warehouse. It decides **which vehicle types to send (Tata Ace / Tata 407 / Eicher 14 ft), which stores each vehicle serves and in what order**, at minimum cost, using real road distances from OSRM.

- **Model:** Heterogeneous Fleet Capacitated VRP with vehicle–store compatibility (formulation in [hfvrp_model.ipynb](hfvrp_model.ipynb), Sections 1–5).
- **Solver:** OR-Tools warm start → Gurobi MILP with a proven optimality gap.
- **Data:** documented in [DATA.md](DATA.md).

## 2. One-Time Setup

### 2.1 Requirements

| Item | Notes |
|---|---|
| Python 3.12+ | Tested on 3.14 |
| Gurobi licence | Academic licence file, e.g. `C:\gurobi\gurobi.lic` |
| Internet | Needed for OSRM (distances and route paths) and map tiles |
| Carto API key (optional) | For the Carto map styles. Esri styles work without a key |

### 2.2 Install

From the project folder in PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

In VS Code, open [hfvrp_model.ipynb](hfvrp_model.ipynb) and select the **`.venv`** kernel (top-right, *Select Kernel → Python Environments → .venv*).

### 2.3 Configure `config.yaml` and `secrets.yaml`

| Key | What to set |
|---|---|
| `solver.gurobi.license_file` | Path to your `gurobi.lic` |
| `osrm.base_url` | OSRM server. The default public server is free but rate-limited |
| `depot` | Warehouse ID, name and coordinates |
| `vehicles` | Capacity (crates), fixed cost, cost per km and number available per type |
| `solver.ortools_time_limit_sec` | Stage 1 time (default 300 s) |
| `solver.gurobi.time_limit_sec` | Stage 2 time (default 1200 s). More time can only tighten the gap |
| `model.forecast_file` | Default forecast used by the notebook |

**API keys** go in a separate file **`secrets.yaml`** in the project folder. It is git-ignored and merged into the config automatically:

```yaml
CARTO_API_KEY: <your Carto key>
```

Without `secrets.yaml` the map simply offers only the Esri styles.

> Never put keys in `config.yaml`, which is committed. The saved `route_map.html` files embed the key; they live in the git-ignored `outputs/` folder.

## 3. Step 1 — Generate the Data (automatic)

**You don't need to do anything:** the notebook's first code cell (cell 7) checks `data/` and runs only the missing steps. On a fresh clone it builds everything; on later runs it skips this step.

| Stage | What it does | Output |
|---|---|---|
| 1/3 | Keeps the 361 stores inside the Delhi-NCR box from `config.yaml → region` | `data/processed/stores_ncr.csv` |
| 2/3 | Generates the fleet, store storage/stock/access and 3 forecast scenarios (seeded, so reproducible) | `data/synthetic/…` |
| 3/3 | Requests the 362 × 362 road distance and time matrix from OSRM (64 requests, about 1.5 min) | `data/processed/nodes.csv`, `distance_km.csv`, `duration_min.csv` |

If the store list is missing, all three steps run. Otherwise only the missing step runs, so OSRM is not called again needlessly.

**Rebuilding after changing `config.yaml`** (region, depot, fleet, store settings or scenarios): existing files are not rebuilt automatically. Either set `REGENERATE_DATA = True` in cell 7 for one run, or run the pipeline from the terminal:

```powershell
.\.venv\Scripts\python.exe src\data_pipeline\run_all.py
```

## 4. Step 2 — Solve and Analyse in the Notebook

Open [hfvrp_model.ipynb](hfvrp_model.ipynb) and run the cells top to bottom (**Run All** works).

| Cells | Section | What happens | Time |
|---|---|---|---|
| 1–6 | Formulation | Problem, assumptions, notation, model, KPIs (markdown) | – |
| 7 | Setup | Generates `data/` if missing, loads config and data. **`FORECAST_FILE` and `REGENERATE_DATA` are set here** | < 1 s (≈1.5 min first time) |
| 8 | Model size | Variable counts and demand summary | < 1 s |
| 10 | Instance | Builds the model input and chooses `outputs/<scenario>/` | < 1 s |
| 12 | **Stage 1: OR-Tools** | Builds the warm-start plan | ~5 min |
| 14 | **Stage 2: Gurobi** | Improves the plan, proves the lower bound and saves results. Shows the Gurobi log | ~20 min |
| 16 | KPIs | Cost, gap, vehicles used, utilisation, cost per crate | < 1 s |
| 18 | Fleet mix | What each vehicle type does | < 1 s |
| 20 | Charts | Utilisation histogram, load vs capacity, cost split | < 1 s |
| 22 | Dispatch sheet | Every route with stop sequence, load, km and cost | < 1 s |
| 24 | Route map | Interactive map on real roads | ~1 min first time |
| 26 | Findings | Interpretation generated from the current results | < 1 s |

**Re-analysing without re-solving:** cells 16–24 read the saved files in `outputs/<scenario>/`. After a solve you can restart the kernel and run cells **7, 10, 16–26** only; skip 12 and 14.

**Quick test:** set `ortools_time_limit_sec: 30` and `time_limit_sec: 60` in `config.yaml` to run the whole notebook in about 2 minutes. The gap will be larger.

## 5. Running a Different Forecast

1. Pick a forecast file:
   - the built-in scenarios: `forecast_base.csv`, `forecast_festive.csv` (+20–40 %), `forecast_low.csv` (−15–25 %) in `data/synthetic/forecasts/`, or
   - your own CSV with exactly these columns:

     ```csv
     store_id,forecast_crates
     29581,34
     29650,41
     ```

     Every store in `data/synthetic/store_params.csv` must appear once.
2. In notebook cell 7, set e.g. `FORECAST_FILE = "data/synthetic/forecasts/forecast_festive.csv"`.
3. Run the notebook from cell 7. Results go to `outputs/festive/`; other scenarios are not overwritten.

The model automatically caps each store's delivery at its free storage space and at the largest vehicle allowed there. The excess is reported as *unserved crates*.

## 7. Using the Route Map

- **Map style:** the layer box (top-right) switches between Carto Positron / Voyager / Dark Matter (needs `CARTO_API_KEY`) and Esri Street Map / Esri Satellite (no key).
- **Vehicle layers:** tick or untick S / M / L to show only some vehicle types.
- **Restricted zones:** tick to show the narrow-lane areas where large trucks are not allowed.
- **Hover a route:** shows vehicle, stops, load / capacity, km and cost.
- **Click a store:** shows its route, stop number, crates delivered and load on arrival.

## 8. Starting Fresh (Reset the Project)

Run these from the project folder in PowerShell.

**Option A: clean generated files, keep the installed packages** (`.venv`) and your key (`secrets.yaml`):

```powershell
Remove-Item -Recurse -Force data, outputs -ErrorAction SilentlyContinue; Get-ChildItem -Path src -Recurse -Directory -Force -Include __pycache__, .ipynb_checkpoints | Remove-Item -Recurse -Force; Get-ChildItem -Force -Name
```

**Option B: full first-time reset**, which also removes and reinstalls the virtual environment:

```powershell
Remove-Item -Recurse -Force data, outputs, .venv -ErrorAction SilentlyContinue; Get-ChildItem -Path src -Recurse -Directory -Force -Include __pycache__, .ipynb_checkpoints | Remove-Item -Recurse -Force
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

After either option:
1. In VS Code, open the notebook, click **Clear All Outputs**, **Restart** the kernel and save.
2. After Option B, re-select the `.venv` kernel.
3. Click **Run All**. Cell 7 rebuilds `data/` automatically (about 1.5 min), then the solver runs (about 25 min).

## 9. Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError` (numpy, gurobipy, …) in the notebook | The wrong kernel is selected. Choose the `.venv` kernel |
| `Model too large for size-limited license` | Gurobi did not find your licence. Check `solver.gurobi.license_file` in `config.yaml` |
| `OSRM HTTP 429` or timeouts | The public OSRM server is rate-limiting. Re-run later, raise `osrm.request_delay_sec`, or point `osrm.base_url` to your own OSRM server |
| Map tiles show **"Access blocked"** | That comes from OpenStreetMap's own tile servers, which block maps opened from a file or notebook. The project uses Carto/Esri instead. Rebuild the map (cell 24) if you have an old `route_map.html` |
| Carto styles blank or grey | Check `CARTO_API_KEY` in `secrets.yaml`, or switch to an Esri style |
| `OR-Tools found no feasible solution` | Not enough vehicles for the demand. Increase `available` in `config.yaml → vehicles` |
| `Forecast missing for stores: […]` | Your forecast CSV lacks some `store_id`s. Every store must be listed |
| Gap still large after the time limit | Expected for a model this size; the plan is still the best found. Increase `solver.gurobi.time_limit_sec` for a tighter bound |
